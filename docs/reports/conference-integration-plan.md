## 1. Final Architecture

שתי מערכות עצמאיות לחלוטין, דומיין ציבורי אחד, פיצול לפי נתיב.

```
                          Browser
                             │  https://netaimolami.org
                      ┌──────▼──────┐
                      │  Cloudflare │  TLS ציבורי · WAF · cache · HSTS מרכזי
                      └──────┬──────┘
                    פיצול לפי קידומת נתיב
              ┌──────────────┴──────────────┐
              │                    Cloudflare Tunnel (מוצפן, יוצא)
   ┌──────────▼──────────┐       ┌──────────▼──────────────────┐
   │ SERVER 1 — WordPress│       │ SERVER 2 — Conference       │
   │ Apache/Nginx + PHP  │       │ Nginx → 127.0.0.1:3000      │
   │ Elementor · MySQL   │       │ Next 15 + Payload 3 · PM2   │
   │ Polylang (en ברירת  │       │ PostgreSQL 16 (localhost)   │
   │ מחדל, he בקידומת)   │       │ אפס פורטים נכנסים           │
   └─────────────────────┘       └─────────────────────────────┘
        אתר · ניווט · מותג            כנסים · משתמשים · Studio
```

שום משתמש לא רואה דומיין שני. שום מערכת לא מחזיקה נתונים של השנייה. הגבול הוא גבול **ניתוב ועיצוב** בלבד — אין API בין השתיים, אין SSO ואין סנכרון.

**מה שמאפשר את כל זה, ואומת בגרסה 2.0 מול 554 קבצי מקור:** מבנה ה־URL של האפליקציה כבר `/{locale}/events/{slug}/...`, ו**אין בקוד אף קישור פנימי מוחלט** — כל 80+ אתרי הבנייה הם תבניות יחסיות. כתובות מוחלטות נבנות בשני מקומות בלבד, ושניהם קוראים `NEXT_PUBLIC_SERVER_URL`. לכן: אין `basePath`, אין `assetPrefix`, אין שכתוב נתיבים. ה־proxy מעביר את הנתיב **כפי שהוא**.

## 2. Server Topology

| | SERVER 1 | SERVER 2 |
|---|---|---|
| תפקיד | האתר הציבורי | פלטפורמת הכנסים |
| סטאק | WordPress + Elementor + MySQL | Next 15 + Payload 3 + PostgreSQL 16 |
| תהליך | PHP-FPM | PM2 (`hason`) + `cloudflared` |
| האזנה | 80/443 | **127.0.0.1:3000 בלבד** |
| מסד | MySQL מקומי | PostgreSQL מקומי, `127.0.0.1:5432` |
| חשיפה ציבורית | דרך Cloudflare | **דרך Cloudflare Tunnel בלבד — אפס פורטים נכנסים** |
| גיבוי | גיבוי אתר | `scripts/backup.sh` (מאמת את הדאמפ בעצמו) |

פורט 3000 לא נפתח בחומת האש — כמתועד ב־`DEPLOY.md` א.2. PostgreSQL קשור ל־loopback ואינו מאזין החוצה. עם Tunnel, גם 80/443 אינם נדרשים כפורטים נכנסים בשרת הכנסים.

## 3. Public URL Ownership

### 3.1 וורדפרס מחזיק

**מאומת מול המערכת החיה** (סעיף 6). **ארכיטקטורת השפות של וורדפרס, מאושרת:** אנגלית היא שפת ברירת המחדל של Polylang ו**אינה נושאת קידומת** — היא יושבת בשורש. עברית יושבת תחת `/he/`. **אין שורש ציבורי `/en/` בוורדפרס, ואין ליצור אחד.**

```
/                              ← דף הבית באנגלית (ברירת מחדל, בלי קידומת)
/he/                           ← דף הבית בעברית
/about-us/                     /he/מי-אנחנו/
/contact-us/                   /he/צרו-קשר/
/privacy-policy/               /he/מדיניות-פרטיות/
/newsletter/                   (אין מקבילה עברית)
/programs/                     /he/programs/
/programs/{slug}/              /he/programs/{slug-עברי}/
/events/                       /he/כנסים/            ← רשימת הכנסים (נוצרו 23.9.26 — ראו 3.4)
/sitemap.xml                   /robots.txt              /favicon.ico
/wp-admin/  /wp-json/  /wp-content/  /wp-includes/  /wp-login.php
כל שאר תוכן האתר הארגוני

⛔ /en/                         ← אינו קיים, ולא ייווצר. ראו 5.1
⏸ /terms, /accessibility        ← DEFERRED. ראו 6.3
```

**שתי אי־סימטריות שחייבות להיות מוצהרות, כי כל קוד שמניח סימטריה יישבר עליהן:**

| | עברית | אנגלית |
|---|---|---|
| דף הבית | `/he/` | **`/`** — לא `/en/` |
| slug של עמוד | בעברית (`מדיניות-פרטיות`) | בלטינית (`privacy-policy`) |

### 3.2 פלטפורמת הכנסים מחזיקה

```
/{locale}/events/{slug}              ← דף נחיתה קינמטי, ציבורי
/{locale}/events/{slug}/*            ← כל תת־נתיב: register, enter, me, me/profile,
                                       me/messages, me/speakers, me/venue,
                                       my-activities, networking, schedule, workshops,
                                       ואחרי ההגירה גם program, speakers, speakers/{id}, info
/{locale}/experiences/{slug}         ← חוויות מסמך  ← נוסף בגרסה 2.0 (החלטה 1)
/{locale}/me/*
/{locale}/enter
/{locale}/connect/*
/studio          /studio/*
/admin           /admin/*
/api             /api/*                ← כולל /api/graphql ו־/api/media
/_next/*
/brand/*         /demo/*                ← נוסף בגרסה 2.0 (החלטה 2)
/placeholder/*   /videos/*              ← נוסף בגרסה 2.0 (החלטה 2)
/icon.png        /apple-icon.png        ← נוסף בגרסה 2.0 (החלטה 2)
/events-sitemap.xml                    ← אם נבחרת אפשרות א' בסעיף 21

/{locale}/terms                        ← ⏸ DEFERRED — נשאר בפלטפורמה כנפילה
/{locale}/accessibility                ← ⏸ DEFERRED — נשאר בפלטפורמה כנפילה
```

`{locale}` = `he` | `en` · `{slug}` = כל מזהה כנס או חוויה חוקי.

**`/en/events/{slug}/*` שייך לפלטפורמה, ונשאר שלה.** העובדה שוורדפרס אינו מגיש `/en/` **אינה** משנה זאת: הפלטפורמה מריצה `localePrefix: 'always'`, ולכן כל נתיב כנס באנגלית נושא `/en/` בהגדרה, ומנותב לפלטפורמה. הדפוס בסעיף 4 תופס `^/(he|en)/events/…` בשתי השפות ללא הבדל. **מה שאינו קיים הוא `/en/` כשורש חשוף — לא `/en/` כקידומת נתיב.** זו הבחנה שקל לפספס והיא קריטית.

### 3.3 מרחבי הנכסים הסטטיים — למה הם קריטיים

**החלטה 2 אושרה: הנכסים נשארים בנתיבי השורש שלהם. כלום לא זז, ו־URL של נכס באפליקציה לא משתנה.**

| נתיב | תוכן | מי מפנה אליו | מה נשבר בלי ניתוב |
|---|---|---|---|
| `/brand/netaim-lockup.png`, `-light.png`, `netaim-mark.png` | הלוגו בשני טיפולים | `src/config/brand.ts` — כל chrome, **וכל מייל יוצא** | לוגו שבור בכל עמוד כנס **ובכל מייל** |
| `/placeholder/scene.jpg` | ה־fallback היחיד לכל סצנה | `cinematic-content.ts`, `opening-service.ts` | כל תמונת גיבוי שבורה |
| `/demo/*.jpg` (6) | תמונות demo | `constants/demo-event.ts` | תוכן demo שבור |
| `/videos/networking-hero.mp4 \| .webm` (~3MB) | וידאו רקע | סצנת networking | וידאו רקע שבור |
| `/icon.png`, `/apple-icon.png` | favicon | `src/app/` | אייקון לשונית שבור |

**חובה על וורדפרס — כלל ארגוני, לא כלל קוד:** אסור ליצור בוורדפרס עמוד, קטגוריה, טקסונומיה, ספריית העלאות או כל נכס ציבורי תחת השמות `brand`, `demo`, `placeholder`, `videos`, `events`, `experiences`, `studio`, `admin`, `api`, `_next`. עמוד וורדפרס בשם אחד מאלה ייבלע על ידי כלל ה־proxy, יגיע לאפליקציה, ויקבל 404. **זה סיכון שנפתר במשמעת ובתיעוד, ולא בקוד** — ולכן הוא רשום כאן במפורש, ולא בהערת שוליים.

**המלצת אכיפה:** לפני כל פריסה, להשוות את רשימת מרחבי השורש בסעיף 3.2 ל־`ls public/` של האפליקציה. נכס חדש ב־`public/` = מרחב שורש חדש = כלל proxy חדש. בלי הבדיקה הזו, הוספת תיקייה ל־`public/` שוברת נכסים בשקט, וכפי שסעיף 30 מראה — **שום בדיקה אוטומטית לא תתפוס את זה**.

### 3.4 הערת גבול — `/events`

> **עודכן 23 בספטמבר 2026, אחרי מדידה מול האתר החי.** הנוסח המקורי של הסעיף
> הזה קבע ש־`/he/events/` הוא עמוד רשימת הכנסים בוורדפרס, וקרא לזה *"נקודת
> ההתנגשות האמיתית היחידה בין שתי המערכות"*. זו הייתה קביעה נכונה לזמנה, והיא
> אינה נכונה יותר. הפסקה המקורית נשמרת כאן כדי שהשינוי ייקרא כהחלטה ולא
> כתיקון שקט.

**מה נמצא.** וורדפרס אינו יכול להגיש שני עמודים תחת אותו slug בהתקנה הזו.
שיתוף slug בין תרגומים הוא מודול של Polylang Pro; המותקן הוא הגרסה החינמית,
שבה `modules/share-slug/` הוא פרסומת למודול ולא מימוש שלו. עמוד עברי עם ה־slug
`events` נוצר, `/he/events/` נפתר לעמוד **האנגלי** והפנה אליו. לכן עמוד הרשימה
העברי נוצר כ־`/he/כנסים/`, בהתאם לדפוס של כל עמוד עברי אחר באתר.

**החלוקה בפועל:**

| נתיב | בעלים |
|---|---|
| `/events/` | וורדפרס — רשימת הכנסים באנגלית |
| `/he/כנסים/` | וורדפרס — רשימת הכנסים בעברית |
| `/he/events/` (בלי slug) | **הפלטפורמה** — 404. אין `events/page.tsx`, רק `events/[slug]` |
| `/he/events/{slug}/…` · `/en/events/{slug}/…` | **הפלטפורמה**, כל המרחב |

**התוצאה המבנית, וזה העיקר: ההתנגשות נעלמה.** אין יותר תחילית משותפת בין שתי
המערכות. וורדפרס מחזיק `/events/` בלי קידומת שפה ואת `/he/כנסים/`; הפלטפורמה
מחזיקה את מרחב `/{locale}/events/` בשלמותו. **כלל ה־proxy בסעיף 4 נשאר כפי
שהוא** — הוא נכון, פשוט מחמיר יותר מהנדרש כיום. הרפיה שלו היא החלטת ניתוב ולא
עדכון תיעוד, ולא נעשתה כאן.

**סתירה שנותרה במסמך ולא הוכרעה כאן.** סעיף 3.3 אוסר ליצור בוורדפרס נכס ציבורי
תחת השם `events`, ועמוד `/events/` הוא בדיוק כזה. בפועל אין תקלה — כלל ה־proxy
תופס רק נתיבים עם קידומת שפה — אבל שני הסעיפים סותרים זה את זה כפי שהם כתובים.
זה דורש הכרעה, ולא שיניתי אף אחד מהם.

### 3.5 Polylang — מי תלוי במה

**וורדפרס ממשיך להשתמש בהתקנת Polylang הקיימת שלו.** לא שונתה בה הגדרה אחת.

**לפלטפורמה יש אפס תלות ב־Polylang**, וזה נמדד ולא הוכרז: `grep` על כל `src/`
אחרי `polylang`, `pll_*`, `wp-json`, `wp-admin`, `xmlrpc` ו־`wpml` מחזיר אפס
תוצאות, והבדיקה הזו מקובעת כטסט ב־`tests/unit/leaving-for-the-website.test.ts`.

* טיפול השפה בפלטפורמה שייך ל־**next-intl**, והוא המקור היחיד לאמת.
* ניתוב הכנסים אינו בודק את Polylang ואינו יודע על קיומו.
* **אין** קריאת API לוורדפרס, אין אימות משותף, אין מצב שפה משותף ואין סנכרון
  קוקיז בין השתיים.
* כל הכתובות של וורדפרס שהפלטפורמה מקשרת אליהן יושבות בטבלה אחת,
  `src/config/wordpress.ts`, ונצרכות דרך `wordpressHref(route, locale)`. אף
  קובץ אחר אינו מחזיק נתיב.

זהו **מצב המימוש הנוכחי**, לא החלטה פתוחה.

## 4. Dynamic Conference Routing Model

הדגם כולו נשען על התאמת דפוס, לא על רשימת כנסים.

```nginx
# שני הדפוסים הקנוניים. שום slug אינו מופיע בהם.
location ~ ^/(he|en)/events/[^/]+(/|$)      { → conference }
location ~ ^/(he|en)/experiences/[^/]+(/|$) { → conference }   # נוסף בגרסה 2.0
```

| נתיב | תוצאה |
|---|---|
| `/events/` | וורדפרס — רשימה באנגלית |
| `/he/כנסים/` | וורדפרס — רשימה בעברית |
| `/he/events/` | הפלטפורמה — 404, אין slug (עודכן 23.9.26, ראו 3.4) |
| `/he/events/netaim-2026` | כנסים |
| `/he/events/netaim-2026/schedule` | כנסים |
| `/he/events/netaim-2026/program` | כנסים (אחרי ההגירה, סעיף 7) |
| `/en/events/netaim-2031/networking` | כנסים — **בלי לגעת בקונפיג** |
| `/he/experiences/onboarding` | כנסים |
| `/en/experiences/{כל slug}` | כנסים |

**איך הכנס נפתר בפועל:** `slug` → Payload → אוסף `events` (`slug` הוא שדה `unique` + `index`, `src/cms/collections/events.ts`) → האירוע, ה־`experience` שלו, ה־`composition` שלו. הרינדור דרך `ExperienceStage`. **אין בקוד מיפוי נתיב→כנס.** הוספת כנס לשנה הבאה היא רשומה ב־CMS ותו לא.

**מה שאסור:** כלל proxy שמזכיר slug מסוים, קבוע `SLUG` בקוד, או רשימת כנסים בקונפיגורציה — בקוד, ב־Nginx, ב־Cloudflare Rules או ב־config של הפריסה.

**הסייג על דפוס התווים — נסגר.** גרסה 1.0 שאלה אם להגביל ל־`[a-z0-9-]+` כדי לצמצם שטח תקיפה, וחששה שזה ישבור slug עברי. **החשש אינו קיים:** `src/features/events/utils/slug.ts` **מרומן עברית לתעתיק לטיני** אות־אות (`כנס חדשנות` → `kns-chdshnvt`) ומסנן `[^a-z0-9]`, כך שכל slug שהמערכת מייצרת הוא ASCII בהגדרה. **ההחלטה: להשאיר `[^/]+`** ולתת לאפליקציה להחזיר 404 — זו התנהגות נכונה ממילא, והיא לא מסתמכת על הנחה לגבי תווים.

### 5.1 שורש השפה — ההכרעה, מאושרת

**ארכיטקטורת השפות של וורדפרס, מאושרת ומאומתת:**

```
וורדפרס אנגלית:   /
וורדפרס עברית:    /he/
שורש /en/:        אינו קיים — ולא ייווצר
```

**הפלטפורמה אינה מניחה ש־`/en/` שייך לוורדפרס.** שני דברים נובעים מזה, והם שונים לחלוטין:

| | מה |
|---|---|
| **`/en/` כקידומת נתיב כנס** | `/en/events/{slug}/*` **שייך לפלטפורמה וממשיך להיות שלה.** אין שינוי, אין סייג. `localePrefix: 'always'` מחייב את הקידומת, והדפוס בסעיף 4 תופס אותה |
| **`/en/` כשורש חשוף** | אינו קיים בשום מערכת. **אף קישור בפלטפורמה לא יצביע אליו** |

**ההכרעה: התיקון נעשה בפלטפורמה, מודע שפה. לא נוצר עמוד `/en/` בוורדפרס כדי לרצות את הפלטפורמה.**

```ts
/* המפה הקנונית. מקום אחד, שתי שפות, אי-סימטריה מוצהרת.
   מיושם בשלב 2 — לא עכשיו. */
const WORDPRESS_HOME: Record<Locale, string> = {
  he: '/he/',   /* חוויית הכנס בעברית חוזרת לבית העברי */
  en: '/',      /* חוויית הכנס באנגלית חוזרת לשורש — לא ל-/en/ */
};
```

**מה זה מתקן בפועל.** `SITE_NAV_LINKS` מגדיר את פריט הבית כ־`path: ''`, ושני ה־nav מרנדרים אותו כ־`` `${home}${link.path}` `` כאשר `` home = `/${locale}` ``. בעברית זה נותן `/he` — תקף. **באנגלית זה נותן `/en` — נתיב שאף מערכת אינה מגישה.** אותו חישוב חוזר בעוד שמונה מקומות, ובהם **יעד ההתנתקות** (`sign-out.ts:31,41`). כלומר בלי התיקון, משתמש אנגלי שמתנתק מגיע ל־404. זה מסלול אמיתי דרך UI קיים, ולא פינה תיאורטית — ולכן הוא נכנס לשלב 2 ולא ל"מתישהו".

**רשימת 9 האתרים המדויקת נמצאת בסעיף 24.4**, כולל שני מקרים מיוחדים:

- `scenes/opening-scenes.tsx:135` — `href: '/'` **בלי שפה בכלל.** נכון באנגלית מעכשיו, **שגוי בעברית** (מבקר עברי מגיע לבית האנגלי). חייב לעבור למפה.
- שני ה־`registerHref` fallback ב־layouts — `` `/${locale}` `` כשאין כנס פעיל. אותו באג.

**מה שנשאר אופציונלי, ואינו חוסם דבר:** הפניית 301 בוורדפרס מ־`/en*` אל המקבילה האנגלית, בשביל מי שמקליד `/en/` ידנית או קישור חיצוני ישן. **זו הפניה, לא עמוד**, ולכן אינה סותרת את ההנחיה. היא הגנה בשכבה שנייה בלבד — הפלטפורמה כבר לא תפיק את הכתובת הזאת אחרי שלב 2. **לא נדרש לייצור.**

**הערה על עדיפות הקוקי:** ה־middleware מפנה `/en/...` → `/he/...` כשקיים `participant_locale=he`. כלומר העדפת שפה שמורה **עוקפת** את הקישור, וזו התנהגות קיימת ומכוונת (מתועדת ב־`event-header.tsx`: *"העדפת שפה שמורה מנצחת את הניווט"*). המפה בסעיף הזה קובעת לאן קישור **מצביע**; הקוקי קובע לאן המבקר **מגיע**. שתיהן נכונות, והן לא מתנגשות — אבל כדאי לדעת שהן קיימות שתיהן כשמדבגים.

אני לא מכריע בהן עכשיו ולא פועל לפיהן — אבל הן יעלו ממילא, ועדיף שיהיו רשומות מאשר שייזכרו מחדש:

**הטבלה הזאת היא ידע שנאסף ואומת, לא הוראת מימוש.** מה ממנה מיושם עכשיו ומה מחכה:

| אודות | `/he/מי-אנחנו/` | `/about-us/` | לפי הצורך |
| תוכניות | `/he/programs/` | `/programs/` | לפי הצורך |

**מה שמיושם בשלב 2: רק שורת הבית.** היא אינה תוכן משפטי, היא מתקנת 404 אמיתי (5.1), והיא מאושרת.

**מה שמחכה לשלב 14: ארבע השורות המסומנות** — כמכלול אחד, אחרי שצוות וורדפרס יאשר את העמודים הסופיים.

```ts
/* הצורה הנדרשת כשהשלב הסופי יגיע — מפה מפורשת לכל שפה, לא תבנית.
   שתי סיבות: ה-slug בעברית הוא בעברית, והאנגלית חיה בשורש בלי קידומת.
   לא מיושם עכשיו. */
const WORDPRESS_LINKS: Record<Locale, Record<string, string>> = {
  he: { home: '/he/', about: '/he/מי-אנחנו/', contact: '/he/צרו-קשר/',
        privacy: '/he/מדיניות-פרטיות/', programs: '/he/programs/' },
  en: { home: '/',    about: '/about-us/',   contact: '/contact-us/',
        privacy: '/privacy-policy/',        programs: '/programs/' },
};
```

**שלוש הערות מימוש שחוסכות באג — תקפות לשתי הקבוצות:**

1. **קידוד.** `next/link` ו־`<a href>` מקודדים עברית ל־percent-encoding אוטומטית. אין צורך לקודד מראש, **ואין לקודד פעמיים** — `encodeURIComponent` על מחרוזת שכבר מכילה `/` ישבור את הנתיב.
2. **הבית אינו סימטרי.** `he` → `/he/`, `en` → `/`. כל קוד שבונה `` `/${locale}` `` נותן `/en` — נתיב שאף מערכת אינה מגישה (5.1).
3. **לאמת מול הייצור לפני כל מימוש.** הטבלה מאומתת מול ההתקנה **המקומית**. אם ה־slug בייצור שונה, המפה משתנה. **`curl -I` לכל יעד, ולאמת 200** — בשלב 7 לשורת הבית, ובשלב 14 לארבע האחרות.

## 7. Conference Public-Route Migration

זו עבודת הקוד היחידה המשמעותית בתוכנית.

### 7.1 המצב היום — ותיקון של הנחה

`src/app/(frontend)/[locale]/(experience)/` מכיל `program/`, `speakers/`, `speakers/[id]/`, `info/`. הם נפתרים לפי `Site.activeConference` — מודל "כנס אחד לובש את האתר", שמתנגש עם וורדפרס.

**תיקון עובדתי שגרסה 1.0 פספסה:** ארבעת העמודים **אינם ציבוריים**. כולם קוראים `await requireParticipant(lang)`, שמפנה כל מי שאינו מזוהה אל `/{locale}/me`. הכינוי "Public-Route Migration" היה שגוי.

**שלוש השלכות:**

1. **סעיף 21 (sitemap):** `src/app/sitemap.ts` מפרסם אותם תחת הערה שאומרת במפורש *"כל רשומה כאן היא עמוד שכל מבקר יכול לפתוח בלי להזדהות"*. **זה אינו נכון היום.** באג קיים, לא תוצאה של האינטגרציה.
2. **סעיף 22 (robots):** ראוי שיחסמו, לא שיותרו.
3. **הנתיבים הישנים:** הטיעון היחיד בעד הפניה היה קישור חיצוני ישן. לעמוד שמפנה אנונימי להתחברות אין קישורים חיצוניים בעלי ערך ואין דירוג. **ההחלטה: הסרה.** הם פשוט לא ינותבו.

### 7.2 היעד

/he/events/{slug}/program        /en/events/{slug}/program
/he/events/{slug}/speakers       /en/events/{slug}/speakers
/he/events/{slug}/speakers/{id}  /en/events/{slug}/speakers/{id}
/he/events/{slug}/info           /en/events/{slug}/info

### 7.3 הצורה המחויבת — קבוצת נתיבים מקוננת

**אושר במפורש: אין להעביר את ה־layout של החוויה מעל `events/[slug]/page.tsx`.**

הנימוק הטכני, במלואו: ל־`(experience)` יש `layout.tsx` עם chrome בהיר (`ExperienceNav` + `ConferenceFooter`, `bg-[var(--x-bg)]`). אם ה־layout הזה ייכנס כ־`events/[slug]/layout.tsx`, הוא **יעטוף גם את `events/[slug]/page.tsx`** — דף הנחיתה הקינמטי, בעל chrome כהה משלו. התוצאה: שני ניווטים זה על זה על עמוד הכנס הציבורי.

**הצורה היחידה שעובדת:**

```
src/app/(frontend)/[locale]/events/[slug]/
├── page.tsx                    ← נשאר. chrome קינמטי. ציבורי. לא נעטף
├── error.tsx  loading.tsx      ← נשארים
├── register/  enter/  me/  my-activities/  networking/  schedule/  workshops/
│                               ← כולם נשארים כפי שהם
└── (experience)/               ← קבוצה חדשה. אינה מופיעה בכתובת
    ├── layout.tsx              ← chrome בהיר. עוטף רק את הארבעה שמתחתיו
    ├── program/  speakers/  speakers/[id]/  info/
```

קבוצה בסוגריים אינה מופיעה בכתובת, ו־`params.slug` עובר אליה מהסגמנט שמעליה. `/{locale}/events/{slug}` שומר על ה־chrome הקינמטי שלו; העמודים המזוהים שומרים על ה־chrome שלהם. **אין חלופה לצורה הזו ב־Next 15.**

### 7.4 המימוש, צעד־צעד (לא מבוצע)

1. יצירת `events/[slug]/(experience)/` והעברת חמשת קובצי הנתיב לתוכה.
2. בכל אחד מהארבעה: החלפת `getActiveConferenceSlug(lang)` ב־`params.slug`. הדפוס כבר קיים ב־`events/[slug]/page.tsx`.
3. התאמת 28 אתרי הקישור (סעיף 24).
4. עדכון ה־snapshot הנעול — **בקריאת diff**, לא באישור עיוור (סעיף 30.3).
5. עדכון `sitemap.ts` ו־`robots.ts` (סעיפים 21–22).
6. `Site.activeConference` — מאבד את תפקידו הציבורי, נשאר בדגם (סעיף 25).

### 7.5 שני נתיבים שנשארים במקומם — החלטות 4 ו־5

**החלטה 4 אושרה.** ארבעת הנתיבים נשארים, בלי מיזוג ובלי שינוי שם:

| `/{locale}/events/{slug}/program` | **התוכנית של הכנס** — כל הסשנים, לכל המשתתפים. תצוגה אחת של המודל המשותף | `requireParticipant` |
| `/{locale}/events/{slug}/schedule` | **הלו"ז שלי** — הסדנאות שהמשתתף הזה בחר, לפי סדר הזמן, עם התראת חפיפה | session |
| `/{locale}/events/{slug}/workshops` | **בחירת סדנאות** — הפעולה, לא התצוגה. קיבולת, רשימת המתנה, הרשמה | session |

## 8. Authentication Architecture

**לא נוגעים.** נשמרים כפי שהם: magic link, `participant_session`, `participant_locale`, טוקן HMAC עם namespace של מטרה, TOTP, `participant-sessions`, `account-sessions`, מודל ההרשמה, ו־access control של Payload.

**מה כן משתנה — ואומת בקוד, לא הונח:**

```
NEXT_PUBLIC_SERVER_URL=https://netaimolami.org
```

שמונה שימושים, וכולם נבדקו:

| קובץ | שורה | מה הוא עושה |
|---|---|---|
| `src/shared/utils/site-origin.ts` | 22 | מקור ההפניות המוחלטות אחרי כניסה |
| `src/features/registration/services/participant-identity-service.ts` | 45 | בסיס הקישורים במייל |
| שם | **369** | `` `${serverUrl()}/${locale}/events/${slug}/enter?token=${raw}` `` — **קישור כניסה ברמת כנס, כבר דינמי לפי slug** |
| שם | **474** | `` `${serverUrl()}/${locale}/enter?token=${raw}` `` — קישור ברמת פלטפורמה |
| `src/infrastructure/email/smtp-channel.ts` | 35 | בסיס לנכסים בתוך המייל — **כולל `/brand/*`** (סעיף 3.3) |
| `src/app/robots.ts` | 18 | כתובת ציבורית ל־sitemap |
| `src/app/sitemap.ts` | 28 | בסיס לכתובות ב־sitemap |
| `src/config/env.ts` | 25-27 | ולידציה — חייב להיות URL מלא, אחרת השרת מסרב לעלות |

**ממצא חשוב:** שורה 369 מוכיחה שקישורי הכניסה **כבר** משובצים לפי כנס ולפי שפה. מודל ריבוי הכנסים נתמך באימות עצמו, לא רק בניתוב.

**האם נדרשת קונפיגורציה נוספת? נבדק — לא.**

- `trustProxy` / `X-Forwarded-Host` — האפליקציה **אינה** מסיקה host מכותרות. היא לוקחת את הכתובת מה־env. אין צורך בהגדרת trusted proxy, וזו הסיבה שאפשר להחליף דומיין בשינוי משתנה אחד.
- **שומר קיים ב־CI:** `tests/unit/architecture-guards.test.ts` אוכף שאף `route.ts` אינו בונה הפניה מ־`nextUrl.origin` בלי `siteOrigin`. ההערה בקובץ מספרת שקישור ה־magic link הראשון מהשרת החי הפנה ל־`localhost`. **השומר הזה הוא מה שעושה את שינוי הדומיין בטוח.**
- Cookie `domain` — לא מוגדר בשום מקום; host-only. בדומיין משותף זה עובד ללא שינוי.
- `sameSite: 'lax'` — מתאים: הכניסה מגיעה מלחיצה על קישור במייל (ניווט top-level).
- `secure` — נגזר מ־`NODE_ENV === 'production'`.
- CSP `form-action 'self'` — שתי המערכות באותו origin.
- **אין CSRF token מפורש.** ההגנה: Server Actions של Next + SameSite + CSP. החלטה ארכיטקטונית קיימת, ראויה לתיעוד בסעיף 30.

## 9. Cookie / Session Behavior

| קוקי | מאפיינים | בדומיין משותף |
|---|---|---|
| `participant_session` | `httpOnly`, `sameSite=lax`, `secure` בייצור, `path=/`, 30 יום | יישלח גם לבקשות וורדפרס |
| `participant_locale` | זהה | זהה |
| `wordpress_logged_in_*` | של וורדפרס | יישלח גם לבקשות האפליקציה |

**אין התנגשות שמות.** אין לאף מערכת יכולת לקרוא את הקוקי של השנייה: הטוקן חתום HMAC בסוד שרק האפליקציה מחזיקה, ואין באפליקציה קוד שמסתכל על קוקיז של וורדפרס.

**הערה חדשה בגרסה 2.0:** `next-intl` מוגדר `localeCookie: false` במכוון (`src/i18n/routing.ts`, עם נימוק מתועד: *"פחות קוקיז זה פחות להצהיר, וספירת הקוקיז בהצהרת הפרטיות נשארת נכונה"*). כלומר **האפליקציה אינה כותבת שום קוקי למבקר אנונימי**. זה משמעותי להצהרת הפרטיות המשותפת: ספירת הקוקיז של הדומיין המשותף היא קוקיז של וורדפרס + שניים של האפליקציה, **ורק אחרי הזדהות**.

**האם לצמצם `path`?** נבחן ונדחה. צמצום ל־`/he/events/` ישבור את `/{locale}/me` ואת `/studio`. **המלצה: להשאיר `path=/` ולתעד בהצהרת הפרטיות** ששתי המערכות חולקות דומיין.

**קאשינג — קריטי:** תשובות שנושאות `Set-Cookie` או תלויות ב־session אסור שייכנסו לקאש של Cloudflare. סעיף 15 מפרט.

## 10. Payload / PostgreSQL Boundary

- PostgreSQL מאזין ל־`127.0.0.1` בלבד. **אין חשיפה ציבורית ואין חוק firewall שמאפשר 5432.**
- Payload רץ **בתוך** תהליך ה־Next (`app/(payload)/`), לא כשרת נפרד. אין פורט נוסף לסגור.
- REST ו־GraphQL של Payload חשופים תחת `/api/*` ו־`/api/graphql`, מוגנים ב־access control ברמת collection כולל סינון לפי ארגון (`src/cms/access.ts`).
- `/admin` חסום בייצור אלא אם `CONTENT_ENGINE_ADMIN=true`.
- **וורדפרס לא נוגע ב־PostgreSQL. לעולם.** אין credentials משותפים, אין קריאה, אין replication.
- בידוד: 28 collections, כל אחד מרכזי נושא `organization` ומסונן לפיו. `tests/integration/isolation.int.test.ts` מוכיח זאת מול Postgres אמיתי, ו־`CI=true` מונע ממנו לדלג בשקט.
- **חוב מתועד שמגביל את סעיף 29:** המסד נבנה ב־`PAYLOAD_DB_PUSH` ולכן אין לו היסטוריית מיגרציות (מתועד ב־`package.json` תחת `_migrations:README`). `migrate` ייכשל על ה־CREATE הראשון. **ההשלכה: אין rollback סכימתי בפעולה אחת** — ראו 29.

## 13. Typography Strategy

**המצב:** האפליקציה מריצה **Heebo** אחת, דרך `next/font/google`, subsets `['hebrew','latin']`, כמשתנה `--font-body`, ו־`--font-display` ממופה אליה. וורדפרס מריץ ארבע משפחות: Montserrat, Open Sans, M PLUS Rounded 1c, Roboto.

**ההחלטה:** וורדפרס הוא מקור האמת → האפליקציה עוברת למשפחות של וורדפרס.

**המימוש הנדרש (לא מבוצע):**

```ts
// src/app/(frontend)/[locale]/layout.tsx — המקום היחיד שמשתנה

const latin = Montserrat({ subsets: ['latin'], weight: ['400','500','700'], variable: '--nt-font-latin' });
const hebrew = Open_Sans({ subsets: ['hebrew','latin'], weight: ['400','500','700'], variable: '--nt-font-hebrew' });
const display = M_PLUS_Rounded_1c({ subsets: ['latin'], weight: ['400','700'], variable: '--nt-font-display-he' });
```

```css
:root      { --nt-font-sans: var(--nt-font-latin), var(--nt-font-hebrew), system-ui; }
[dir="rtl"]{ --nt-font-sans: var(--nt-font-hebrew), system-ui;
             --nt-font-display: var(--nt-font-display-he), var(--nt-font-hebrew), system-ui; }
--font-body: var(--nt-font-sans);      /* alias — שום קומפוננטה לא משתנה */
--font-display: var(--nt-font-display);
```

**שלוש עובדות לפני אישור:**

1. `next/font` מאחסן את הגופנים **עצמית** תחת `/_next`, ולכן **אין צורך בשינוי CSP** (`font-src 'self'` נשאר תקף). יתרון ממשי מול טעינה מ־Google — **ובפרט כאן**, כי ה־CSP של האפליקציה הוא `font-src 'self' data:` בלבד, ומעבר ל־Google Fonts היה מחייב לפתוח אותו.
2. Heebo היא משפחה אחת, variable, שמכסה עברית ולטינית באותו קול. החלפתה בשלוש **מוסיפה הורדות** ומפצלת את הקול בין השפות. עלות אמיתית.
3. M PLUS Rounded 1c כבדה מאוד (882 קובצי face בהתקנה המקומית). עם subsets מוגדרים זה מצטמצם, אבל צריך למדוד.

**המלצה: לאשר את המעבר, אבל לצמצם לשתי משפחות** בכנסים (Montserrat ללטינית, Open Sans לעברית) ולוותר על M PLUS Rounded 1c בכותרות האפליקציה. משמר את ה־DNA, מוריד משקל. **לא מבוצע — ממתין להכרעה** (סעיף 32).

**אין מה לאחד.** כל מערכת מגישה את המסמך שלה ומצהירה `dir` בעצמה. שכבת הטוקנים המשותפת קוראת `[dir="rtl"]` ועובדת בשתיהן ללא שינוי.

**סייג חדש בגרסה 2.0:** מתג השפה של וורדפרס מצביע **עברית → `/he/ראשי/`** ו**אנגלית → `/`**, כלומר הוא מחזיר את המבקר לדף הבית, לא לעמוד המקביל, כשאין תרגום. המתג של האפליקציה שומר את הנתיב. **שתי התנהגויות שונות באותו דומיין** — נדרש תיאום ויזואלי כדי שלא ייראו כבאג.

## 15. Cloudflare Routing Strategy

שתי טופולוגיות. שתיהן תקפות; הן נבדלות בשאלה איפה נופל הפיצול.

**אפשרות א׳ — פיצול ב־Cloudflare (מומלצת).** Origin Rules מפנות לפי דפוס נתיב לאחד משני ה־origins. אין hop נוסף, שרת וורדפרס לא נושא את תעבורת הכנסים, וכל מערכת נופלת בנפרד.
*לאימות לפני החלטה:* מספר ה־Origin Rules המותר בתוכנית ה־Cloudflare הנוכחית. **לא אמת שלא בדקתי.** מספר הדפוסים הנדרש גדל בגרסה 2.0 (experiences + ארבעה מרחבי נכסים), ולכן הבדיקה הזו חשובה יותר מקודם.

**אפשרות ב׳ — פיצול ב־Nginx בקצה** על שרת וורדפרס, שמעביר הלאה. פשוט יותר לניפוי, אבל שרת וורדפרס הופך לנקודת כשל של הכנסים, ונוסף hop.

**הגדרות Cloudflare הנדרשות בשתי האפשרויות:**

- SSL/TLS: **Full (strict)**. לא Flexible — `DEPLOY.md` כבר מזהיר שזה יוצר לולאת הפניות.
- Always Use HTTPS: דלוק.
- **HSTS: ראו סעיף 19.** לא להדליק כחלק מהגדרות הבסיס.
- **חוקי Cache — קריטי:**
  - `bypass` מלא: `/he/me/*`, `/en/me/*`, `/api/*`, `/studio*`, `/admin*`, וכל תשובה עם `Set-Cookie`.
  - `cache` אגרסיבי: `/_next/static/*` (immutable, שנה).
  - `cache` ארוך: `/brand/*`, `/placeholder/*`, `/demo/*`, `/videos/*`, `/icon.png`, `/apple-icon.png` — נכסים סטטיים אמיתיים, שאינם נושאים cookie. **חדש בגרסה 2.0**, ומוריד עומס אמיתי (הווידאו לבדו ~3MB).
  - `/he/events/*`, `/en/events/*`, `/{locale}/experiences/*`: העמודים `force-dynamic` ותלויי cookie — **bypass**, או Edge Cache קצר מאוד עם `Vary: Cookie`. ברירת המחדל הבטוחה: bypass.
- WAF: הגנה בסיסית; חריג ל־`/api/notifications/dispatch` אם ה־cron יוצא דרך הרשת (היום הוא קורא ל־`127.0.0.1`).
- Rate limiting: על `/{locale}/enter` ועל נתיבי ההרשמה. באפליקציה כבר קיימת collection `rate-limits` — הגנה בשתי שכבות.

## 16. Secure Transport Strategy — Cloudflare Tunnel

**אושר.** בין הקצה לשרת הכנסים עוברים קוקיז של session. **HTTP גלוי מעל האינטרנט הציבורי פסול.**

### 16.1 היעד המאושר

```
Browser
  → Cloudflare                         (TLS ציבורי, WAF, cache)
  → Cloudflare Tunnel                  (מוצפן, חיבור יוצא מהשרת)
  → Conference server
  → Nginx                              (127.0.0.1)
  → Next.js / Payload                  (127.0.0.1:3000)
  → PostgreSQL                         (127.0.0.1:5432)
```

### 16.2 דרישות מחייבות

- PostgreSQL אינו חשוף ציבורית, בשום תנאי.
- **5432 סגור.** loopback בלבד.
- **3000 סגור.** loopback בלבד.
- **אין HTTP גלוי** מעל האינטרנט הציבורי, בשום קטע.
- **שרת המקור אינו נגיש בעקיפת Cloudflare.** עם Tunnel זה מתקיים בהגדרה — אין פורט נכנס לפנות אליו.
- **זמינות ה־Tunnel מנוטרת.** `cloudflared` הוא תהליך, ותהליך נופל.

### 16.3 היתרון שאין לאפשרות האחרת

**זה לא העדפה — יש לזה נימוק קשה בקוד ובקונפיג הקיים.** התעודה בשרת הכנסים הונפקה ל־`netaim26.org` ול־`www` בלבד (`DEPLOY.md` א.12). אם וורדפרס או Cloudflare יפנו HTTPS אל שרת הכנסים עם `Host: netaimolami.org`, **אימות שם המאחז ייכשל** — אלא אם תונפק תעודה נוספת לשם הזה, ותתוחזק.

**Cloudflare Tunnel אינו דורש תעודה בצד המקור כלל.** הוא מייתר את הבעיה במקום לפתור אותה. זה היתרון המכריע, ולא ה"אפס פורטים" — שגם הוא נכון.

### 16.4 ניטור — דרישה, לא המלצה

| מה | איך | למה |
|---|---|---|
| תהליך `cloudflared` | `systemd` עם `Restart=always`, או PM2 לצד `hason` | תהליך שנפל = האתר למטה, בלי שגיאה בשרת |
| בריאות מקצה לקצה | בדיקה חיצונית ל־`https://netaimolami.org/api/health` | `/api/health` כבר קיים ואינו חושף גרסאות או קונפיגורציה |
| התראה | לכתובת שאינה על אותו דומיין | אם המייל יוצא דרך המערכת שנפלה, ההתראה לא תגיע |

### 16.5 הנפילה המתועדת

| אפשרות | מצב | תנאים |
|---|---|---|
| **Cloudflare Tunnel** | ✅ **מאושר, ראשי** | ניטור התהליך; אפס פורטים נכנסים |
| HTTPS ל־origin + Full (strict) | 📋 **נפילה מתועדת** | תעודה תקפה ל־`netaimolami.org` **במקור**; 443 מוגבל לטווחי Cloudflare; תחזוקת רשימת ה־IP |
| WireGuard בין הקצה לשרת הכנסים | רק אם נבחר פיצול ב־Nginx בקצה (15.ב) | מוסיף רכיב תפעולי |
| HTTP גלוי | ❌ **פסול** | — |

**הרגע שבו ההחלטה הזו מתממשת הוא לפני שינוי ה־DNS, לא אחריו.**

## 17. Nginx Requirements (Conference Origin)

מה שקיים (`DEPLOY.md` א.10) נשאר; להלן מה שחייב להיות נכון בדומיין המשותף.

```nginx
server {
    # מאומת: הקונפיג הקיים מכיל netaim26.org בלבד. הוא כן נתפס בפועל —
    # הוא ה-site היחיד שמופעל ולכן ברירת המחדל *במקרה*. להסתמך על מקריות
    # בקונפיג חזית זה מה שנשבר בשינוי הבא. מוצהר במפורש:
    server_name netaimolami.org netaim26.org;

    client_max_body_size 2m;              # ברירת מחדל שמרנית — סעיף 18

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade            $http_upgrade;
        proxy_set_header Connection         'upgrade';
        proxy_set_header Host               $host;
        proxy_set_header X-Real-IP          $remote_addr;
        proxy_set_header X-Forwarded-For    $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto  $scheme;
        proxy_read_timeout 120s;
    }

    # תשובות מוזרמות (Suspense/SSE) — buffering ישבור אותן
    location ~ ^/(he|en)/me/notifications {
        proxy_buffering off;
        proxy_pass http://127.0.0.1:3000;
    }

    # נתיבי העלאה בלבד — סעיף 18
    location ~ ^/studio/ {
        client_max_body_size 200m;
        proxy_request_buffering off;
        proxy_read_timeout 600s;
        proxy_pass http://127.0.0.1:3000;
    }
}
```

**נקודות שחייבות להיאכף:**

- `server_name` מוצהר, לא נגזר ממקריות.
- `proxy_buffering off` לפחות לנתיבי ההתראות. לבדוק גם את נתיבי החוויה, שמשתמשים ב־`Suspense`.
- אין צורך ב־`X-Forwarded-Host` — האפליקציה אינה קוראת אותו.
- לא לפתוח 3000. לא לחשוף `/admin` מחוץ ל־allowlist.
- **עם Tunnel** ה־Nginx הזה מקבל תעבורה מ־`cloudflared` המקומי, לא מהאינטרנט. הכללים זהים; ההבדל הוא שאין פורט נכנס.

## 18. Upload / Request Body Size Strategy

**סעיף חדש בגרסה 2.0, לפי החלטה 8.**

### 18.1 מה נמצא — אי־התאמה קיימת

| שכבה | הערך היום | מקור |
|---|---|---|
| Nginx | `client_max_body_size 50M` | `DEPLOY.md` א.10 |
| Next Server Actions | `bodySizeLimit: '200mb'` | `next.config.ts` |

ההערה ב־`next.config.ts` אומרת במפורש שהערך *"נשמר שווה ל־`client_max_body_size` של Nginx"*. **הם אינם שווים.** העלאה בין 50MB ל־200MB נחסמת ב־Nginx ומחזירה 413 לפני שהיא מגיעה לאפליקציה. `DEPLOY.md` אף מתעד 413 כתקלה מוכרת. **זה באג קיים, ולא תוצאה של האינטגרציה** — אבל הוא יתחדד כשיתווסף proxy שני בשרשרת, כי אז יש **שלוש** תקרות ולא שתיים.

### 18.2 ההחלטה — ברירת מחדל שמרנית, חריגים לפי נתיב

**החלטה 8 אושרה: לא להעלות את כל האפליקציה ל־200M.** גוף בקשה של 200MB על כל נתיב הוא שטח תקיפה — נתיב שאינו מעלה כלום יקבל את הזכות לקבל 200MB, ותקיפת exhaustion פשוטה תמלא את הדיסק או את הזיכרון.

```
ברירת מחדל גלובלית:  2MB      ← טופסי הרשמה, פרופיל, נטוורקינג, הכול
נתיבי העלאה בלבד:    200MB    ← רק מה שמזוהה ב-18.3
```

### 18.3 הנתיבים שדורשים בדיקה לפני קביעה

**מה שאני יכול לומר מהקוד שקראתי:**

| נתיב | למה | מקסימום |
|---|---|---|
| `/studio/**` — העלאות מדיה בסטודיו | `Media` מקבל `video/mp4`, `video/webm`. הסטודיו מעלה דרך Server Actions, ולכן `bodySizeLimit` הוא התקרה האמיתית. ההערה בקוד מציינת `MAX_VIDEO_BYTES` | **200MB** |
| `/api/media/**` — העלאות Payload | ערוץ העלאה נוסף כשעובדים מול ה־API ישירות | 200MB |
| `/{locale}/me/profile` — תמונת פרופיל | `MAX_PHOTO_BYTES = 5 * 1024 * 1024` — **מאומת בקוד** | **5MB** |
| כל השאר | טופסי טקסט | 2MB |

**בדיקה שחייבת להתבצע לפני שקובעים, ולא בוצעה:**

1. לאתר את `MAX_VIDEO_BYTES` בקוד ולקרוא את ערכו בפועל. הוא **מקור האמת**, ושלוש התקרות מתיישרות אליו — לא להפך.
2. לוודא שהעלאות הסטודיו עוברות רק תחת `/studio/**` ולא גם דרך `/api/media` בזרימה שלא קראתי.
3. לבדוק את `logistics/export` ו־`activity/import` (`(console)/logistics/export`, `(console)/activity/import`) — ייבוא גיליון או ייצוא עשויים לדרוש תקרה אחרת.

**כלל התיישרות — שלוש שכבות, לכל נתיב בנפרד:**

```
Nginx client_max_body_size  ==  Next bodySizeLimit  ==  מגבלת האפליקציה
```

**הקטנה מביניהן היא מה שהמפעיל פוגש.** ואם Cloudflare בשרשרת — **הוא השכבה הרביעית**, ויש לו תקרה משלו לפי תוכנית. **לאמת אותה לפני שמבטיחים 200MB למפעיל.** בתוכנית Free התקרה נמוכה משמעותית, וזה עלול לרוקן את כל הסעיף הזה מתוכן.

**לא משנים קונפיגורציה עכשיו.** הסעיף הזה מגדיר את האסטרטגיה ואת רשימת הבדיקות.

## 19. HSTS Strategy

**סעיף חדש בגרסה 2.0, לפי החלטה 7.**

### 19.1 הבעיה

`next.config.ts` מחזיר את כותרות האבטחה על `source: '/:path*'` — **כל נתיב** — ובכללן:

```
Strict-Transport-Security: max-age=63072000; includeSubDomains; preload
```

בדומיין משותף, הכותרת הזאת מגיעה מהפלטפורמה אבל **חלה על כל `netaimolami.org` ועל כל תתי־הדומיינים שלו, לשנתיים**, ברגע שמבקר טוען עמוד כנס אחד. אם קיים תת־דומיין שמוגש ב־HTTP בלבד — staging, mail, כלי פנימי — **הוא ייפול לאותו מבקר, ואי אפשר לבטל את זה מצד השרת.** דפדפן שקיבל את הכותרת מכבד אותה עד שהיא פגה. `preload` מחמיר עוד: היא בקשה להיכנס לרשימה מוטבעת בדפדפנים, והיציאה ממנה אורכת חודשים.

**זו ההשלכה המשמעותית ביותר של שיתוף דומיין שאינה ניתנת לגלגול לאחור בפעולה אחת.**

### 19.2 האסטרטגיה המאושרת

**HSTS בשליטה מרכזית ב־Cloudflare. האפליקציה אינה כופה מדיניות גלובלית על דומיין משותף.**

| # | כלל | מצב |
|---|---|---|
| 1 | **HTTPS הוא חובה.** Always Use HTTPS דלוק ב־Cloudflare; כל HTTP מופנה | מיד |
| 2 | **HSTS יופעל מרכזית ב־Cloudflare**, לא מכותרת של האפליקציה | אחרי 3 |
| 3 | **`preload` לא מודלק.** לא בהשקה, ולא כחלק מ"הגדרות בסיס" | החלטה נפרדת בעתיד |
| 4 | **לאמת שכל תת־דומיין רלוונטי תומך HTTPS** — לפני כל שקילה של `includeSubDomains` | **חוסם את 5** |
| 5 | **`includeSubDomains` נשקל רק אחרי 4** | אחרי 4 |
| 6 | `preload` היא החלטה מפורשת ומאוחרת, מחוץ להשקה | עתיד |

### 19.3 מה זה אומר לקוד — ולא מבוצע

`next.config.ts` שולח `includeSubDomains; preload` היום. בדומיין משותף זה סותר את כלל 3 וכלל 5 לעיל. **שלוש דרכים, וההכרעה טכנית ולכן אני כן ממליץ:**

| | גישה | הערכה |
|---|---|---|
| **א** | להסיר את כותרת ה־HSTS מ־`next.config.ts` ולתת ל־Cloudflare להיות המקור היחיד | **מומלצת.** מקור אמת אחד, בשליטה מרכזית, בלי צורך בפריסה כדי לשנות מדיניות |
| ב | לצמצם ל־`max-age=31536000` בלי `includeSubDomains` ובלי `preload` | שומר הגנה בסיסית גם אם Cloudflare מוגדר לא נכון. שתי מדיניויות שצריך לסנכרן |
| ג | להשאיר כמו שהוא | **סותר את החלטה 7.** לא אפשרות |

**המלצה: א׳.** מקור אחד. **החריג:** אם מישהו יעקוף את Cloudflare ויפנה לשרת ישירות, לא תהיה HSTS — אבל עם Tunnel זה בלתי אפשרי ממילא (16.2), ולכן החריג אינו קיים בטופולוגיה שנבחרה. **שתי ההחלטות מחזקות זו את זו.**

### 19.4 בדיקה חובה לפני כלל 5

לרשום את כל תתי־הדומיינים של `netaimolami.org` הקיימים היום — כולל mail, staging, כלים פנימיים, כל מה שמוגדר ב־DNS של Cloudflare — ולוודא לכל אחד HTTPS תקף. **תת־דומיין אחד ב־HTTP הוא סיבה מספקת לא להדליק `includeSubDomains`.** הבדיקה הזו לא בוצעה ואינה יכולה להתבצע מכאן: היא דורשת גישה ל־DNS.

## 21. Sitemap Strategy

**וורדפרס מחזיק את `/sitemap.xml`** (Yoast, פעיל, מאומת: `sitemap_index.xml` → `page-sitemap.xml` + `programs-sitemap.xml`).

### 21.1 הבאג הקיים שחייב תיקון

`src/app/sitemap.ts` מפרסם שמונה נתיבים בשתי השפות: `''`, `/program`, `/speakers`, `/info`, `/contact`, `/accessibility`, `/privacy`, `/terms` — תחת הערה שכותבת *"כל רשומה כאן היא עמוד שכל מבקר יכול לפתוח בלי להזדהות"*.

**שלוש מהן כלל אינן ציבוריות:** `/program`, `/speakers`, `/info` מוגנות ב־`requireParticipant` ומפנות אנונימי להתחברות. **ה־sitemap מפנה זחלנים לשלושה עמודים שמחזירים הפניה.** באג קיים, לא תוצאה של האינטגרציה, וטעון תיקון בכל מקרה.

וארבע נוספות (`/contact`, `/privacy`, `/terms`, `/accessibility`) עוברות לוורדפרס, ולכן לא יהיו שלו.

### 21.2 הכלל המאושר

**ה־sitemap של הפלטפורמה מכיל רק מה שציבורי באמת.** עמוד שמוגן ב־`requireParticipant` **אינו נכנס ל־sitemap**, בשום מקרה.

| נתיב | ציבורי? | ב־sitemap? |
|---|---|---|
| `/{locale}/events/{slug}` | ✅ פתוח | ✅ **כן** |
| `/{locale}/experiences/{slug}` | ✅ פתוח | ✅ כן — **אם הוא אכן מיועד לאינדוקס.** ראו 21.4 |
| `/{locale}/events/{slug}/register` | ✅ פתוח | ✅ כן |
| `/{locale}/events/{slug}/program` | ❌ `requireParticipant` | ❌ **לא** |
| `/{locale}/events/{slug}/speakers` | ❌ `requireParticipant` | ❌ **לא** |
| `/{locale}/events/{slug}/info` | ❌ `requireParticipant` | ❌ **לא** |
| `/{locale}/events/{slug}/{schedule,workshops,my-activities,me,networking}` | ❌ session | ❌ לא |
| `/{locale}/me/*`, `/studio`, `/admin`, `/api` | ❌ | ❌ לא |
| `/{locale}/{privacy,terms,accessibility,contact}` | ✅ פתוח, **בפלטפורמה, DEFERRED** | ❌ **לא** — ראו 21.5 |

### 21.3 המבנה המאושר

```
/sitemap.xml            → וורדפרס (Yoast). אינדקס האתר
/events-sitemap.xml     → הפלטפורמה. כנסים וחוויות, דינמי
```

**הגרסה הדינמית חייבת לשאוב את רשימת הכנסים מ־Payload**, לא מרשימה קשיחה. המימוש הנדרש:

```ts
/* קונצפטואלי. לא מבוצע. */
const events = await listPortalEvents(locale);   // כנסים שפורסמו בלבד
return SUPPORTED_LOCALES.flatMap((locale) =>
  events.map((e) => ({ url: `${base}/${locale}/events/${e.slug}`, ... })),
);
```

`listPortalEvents` הוא **בדיוק** הקורא שכבר משמש את דף הנחיתה ואת ה־portal, והוא מחזיר כנסים שפורסמו בלבד. **אין צורך בשאילתה חדשה, ואין רשימה שמישהו צריך לתחזק.** כנס חדש נכנס ל־sitemap ברגע שהוא מפורסם — בלי פריסה.

**החיבור בין השניים** נעשה בשורת `Sitemap:` ב־`robots.txt` של וורדפרס (סעיף 22), לא בקוד.

### 21.4 מה שנשאר להכרעה

**האם `/{locale}/experiences/{slug}` מיועד לאינדוקס?** הנתיב פתוח לציבור, ולכן זחלן יגיע אליו אם יקושר. אבל חוויות מסמך הן לעיתים תוכן פנימי — onboarding, מסמך תהליך — שפתוח מפני שאין בו סוד, ולא מפני שמישהו רוצה שיימצא ב־Google. **החלטת מוצר** (סעיף 32).

### 21.5 העמודים המשפטיים בתקופת הביניים — כלל שמונע נזק ל־SEO

בין עכשיו ובין שלב 14, **שתי המערכות מגישות תוכן משפטי באותו דומיין**: וורדפרס ב־`/privacy-policy/` ו־`/he/מדיניות-פרטיות/`, והפלטפורמה ב־`/{locale}/privacy`, `/{locale}/terms`, `/{locale}/accessibility`, `/{locale}/contact`.

**הכלל בתקופת הביניים:**

- **העמודים המשפטיים של הפלטפורמה אינם נכנסים לאף sitemap.** לא ל־Yoast (הוא לא מכיר אותם) ולא ל־`events-sitemap.xml` (סעיף 21.2).
- **`src/app/sitemap.ts` מפסיק לפרסם אותם.** הוא מפרסם אותם היום, ואחרי שוורדפרס יפרסם את שלו זה יהפוך לתוכן כפול על אותו דומיין — בדיוק מה שמנוע חיפוש מעניש עליו.
- **הם נשארים נגישים במלואם לכל מבקר.** אי־הכללה ב־sitemap אינה חסימה ואינה הסרה: היא רק אומרת "אל תזחל לכאן מיוזמתך". קישור ישיר, קישור מה־footer וקישור חיצוני ממשיכים לעבוד במלואם — וזו בדיוק הדרישה החוקית.
- **לשקול `robots: { index: false }` ב־metadata של ארבעת העמודים** בתקופת הביניים. זו הגנה שנוסעת עם הקוד ולא עם קובץ בשרת אחר — אותה תבנית שכבר קיימת ב־`me/layout.tsx`. **הערה: זה שינוי קוד, ולכן לא מבוצע עכשיו** ונרשם כפריט לשלב 8.

**למה זה חשוב עכשיו ולא בשלב 14:** תוכן משפטי כפול באינדקס הוא נזק שמצטבר בשקט ולוקח שבועות להתנקות. עדיף למנוע אותו ברגע שהדומיין משותף, ולא לתקן אותו אחר כך.

## 22. Robots Strategy

**וורדפרס מחזיק את `/robots.txt`.** הקובץ הסופי חייב לשמר את כל האיסורים שהאפליקציה מגדירה היום (`src/app/robots.ts`), כי הנתיבים קיימים תחת אותו דומיין — **ולהוסיף את מה שגרסה 1.0 פספסה**.

```
User-agent: *
Allow: /

# האזור האישי
Disallow: /he/me/
Disallow: /en/me/

# כניסה וטוקנים — לעולם לא לאינדוקס
Disallow: /he/enter
Disallow: /en/enter
Disallow: /he/connect
Disallow: /en/connect

# מערכת
Disallow: /studio
Disallow: /studio/
Disallow: /admin
Disallow: /admin/
Disallow: /api/

# עמודי כנס מוגנים ב-requireParticipant — חדש בגרסה 2.0.
# זחלן שמגיע אליהם מקבל הפניה להתחברות. אין ערך באינדוקס, ויש
# נזק: Google מדווח על שרשרת הפניות.
Disallow: /he/events/*/program
Disallow: /en/events/*/program
Disallow: /he/events/*/speakers
Disallow: /en/events/*/speakers
Disallow: /he/events/*/info
Disallow: /en/events/*/info
Disallow: /he/events/*/schedule
Disallow: /en/events/*/schedule
Disallow: /he/events/*/workshops
Disallow: /en/events/*/workshops
Disallow: /he/events/*/my-activities
Disallow: /en/events/*/my-activities
Disallow: /he/events/*/me
Disallow: /en/events/*/me
Disallow: /he/events/*/networking
Disallow: /en/events/*/networking

Sitemap: https://netaimolami.org/sitemap.xml
Sitemap: https://netaimolami.org/events-sitemap.xml
```

**מה לא לחסום — במפורש:** `/{locale}/events/{slug}` עצמו, ו־`/{locale}/events/{slug}/register`. אלה העמודים שכל המאמץ קיים בשבילם.

**הערה על תחביר:** `Disallow: /he/events/*/program` משתמש ב־wildcard. Google ו־Bing תומכים; זחלנים קטנים לא בהכרח. **שכבת ההגנה שאינה תלויה בזה:** העמודים מוגנים ב־`requireParticipant` בצד השרת. robots.txt הוא נימוס לזחלן, לא בקרת גישה. ההגנה האמיתית היא הקוד, והיא קיימת.

**שכבה שלישית שכבר קיימת:** `src/app/(frontend)/[locale]/me/layout.tsx` מצהיר `robots: index:false, follow:false, nocache` על כל עץ ה־`/me`. גם אם robots.txt ישתבש, העמודים האישיים מסומנים בתשובה עצמה. **שווה לשקול להוסיף הצהרה דומה ל־layout של `(experience)`** אחרי ההגירה — הגנה שנוסעת עם הקוד ולא עם קובץ בשרת אחר.

## 23. Old-Domain Migration Strategy

`netaim26.org` נשאר חי בזמן ההגירה וה־QA, ומגיש את דף הנחיתה של הכנס הפעיל (החלטה 6). **ההפניה לא מיושמת עכשיו.**

### 23.1 הנכס הקריטי

קישורי magic link שכבר נשלחו במייל נושאים:

```
https://netaim26.org/{locale}/events/{slug}/enter?token=…
https://netaim26.org/{locale}/enter?token=…
```

**ההפניה חייבת לשמר שלושה דברים, וכולם נדרשו במפורש:**

| מה | למה | מה נשבר בלעדיו |
|---|---|---|
| **נתיב** | הטוקן צמוד לנתיב הכניסה | המשתמש מגיע לדף הבית ולא למסלול הכניסה |
| **שפה** | `/he/` מול `/en/` הוא סגמנט בנתיב | המשתמש מקבל את השפה הלא נכונה, ועם `participant_locale` שמור — הפניה נוספת |
| **query string** | **`?token=…` הוא הטוקן עצמו** | **הטוקן אובד. המשתמש מגיע לעמוד כניסה ריק, והקישור שנשלח אליו במייל בוזבז** |

### 23.2 המימוש

מכיוון שמבנה הנתיבים זהה בשני הדומיינים, הפניה גורפת עובדת:

```nginx
# מוצג כדוגמה. לא מיושם.
return 301 https://netaimolami.org$request_uri;
```

**`$request_uri` הוא הצורה הנכונה** — הוא כולל את הנתיב ואת ה־query string כאחד. `$uri` **אינו** כולל את ה־query, ושימוש בו כאן הוא בדיוק הבאג שישבור כל טוקן שנשלח. אם ההפניה נעשית ב־Cloudflare Rules ולא ב־Nginx, לאמת ש־"preserve query string" דלוק.

### 23.3 הסדר

1. `NEXT_PUBLIC_SERVER_URL` מתעדכן → קישורים **חדשים** יוצאים לדומיין החדש.
2. להמתין מחזור חיים של קישור ישן. **לאמת את חלון התפוגה בפועל** ב־`email-verification-service` ובמרחב הטוקנים — לא להעריך.
3. רק אז להפעיל את ההפניה הגורפת.
4. `netaim26.org` נשאר רשום ומפנה **לפחות שנה**.
5. `server_name` ב־Nginx מכיל את שני הדומיינים בזמן החפיפה (סעיף 17).
6. **בדיקה לפני שמכריזים על סיום:** לשלוח קישור כניסה אמיתי לכתובת בדיקה **לפני** ההפניה, ללחוץ עליו **אחרי**, ולאמת שהכניסה הצליחה. זו הבדיקה היחידה שמוכיחה ששלושת השימורים עובדים.

## 24. Link Inventory

## 26. Local Development Strategy

היום: וורדפרס ב־XAMPP על `http://localhost/netaim`, האפליקציה על `http://localhost:3000`. שני origins, ולכן הקוקיז והניתוב אינם מתנהגים כמו בייצור.

**המוצע:** proxy מקומי קל (Nginx של XAMPP, Caddy או `http-proxy`) על פורט יחיד — `http://localhost:8080` — שמחקה **בדיוק** את כללי הייצור:

```
^/(he|en)/events/[^/]+(/|$)        → localhost:3000
^/(he|en)/experiences/[^/]+(/|$)   → localhost:3000
^/(he|en)/(me|enter|connect)(/|$)  → localhost:3000
^/(studio|admin|api|_next)(/|$)    → localhost:3000
^/(brand|demo|placeholder|videos)/ → localhost:3000
^/(icon|apple-icon)\.png$          → localhost:3000
כל השאר                            → localhost/netaim
```

ואז `NEXT_PUBLIC_SERVER_URL=http://localhost:8080`. כך באגי ניתוב מתגלים בלפטופ ולא בייצור. `secure` על הקוקיז כבוי אוטומטית בפיתוח, ולכן HTTP מקומי עובד.

**הערה על הסביבה המקומית:** וורדפרס יושב בתת־ספרייה `/netaim/`. ה־proxy המקומי חייב **להסיר את הקידומת** בצד הכנסים ולשמור אותה בצד וורדפרס — אחרת המקומי לא ידמה את הייצור, שבו וורדפרס בשורש.

**מגבלה:** סביבת ה־workspace של Claude על המחשב הזה שבורה (עדכון Windows מ־8.9), ולכן אני יכול לקרוא ולכתוב קבצים אבל **לא להריץ פקודות מקומית**. הרצת ה־proxy היא עליך. קריאת האתר לצורך סעיף 6 נעשתה דרך הדפדפן, שכן עובד.

## 27. Staging Strategy

- דומיין: `staging.netaimolami.org`, **חסום מאינדוקס** (Cloudflare Access או basic auth בקצה — לא רק robots).
- **⚠ תשומת לב מסעיף 19:** תת־דומיין של `netaimolami.org`. אם `includeSubDomains` יודלק, **staging חייב HTTPS תקף**. זו דוגמה קונקרטית לכלל 4 בסעיף 19.2 — והיא כבר קיימת בתוכנית.
- **מסד נתונים נפרד.** לא להצביע staging על מסד הייצור.
- `PAYLOAD_DB_PUSH` כבוי, כמו בייצור.
- **מייל:** להשאיר `SMTP_HOST` ריק. זו התנהגות מתוכננת — האפליקציה מתעדת הודעות בלי לשלוח (`src/config/env.ts`, הערה מפורשת). כך אף משתתף אמיתי לא מקבל מייל מ־staging.
- אותם כללי proxy בדיוק, כדי ש־staging יבדוק את הארכיטקטורה ולא רק את הקוד.
- **העמודים המשפטיים של הפלטפורמה חייבים להישאר נגישים ב־staging** (6.3). staging הוא בדיוק המקום שבו האפליקציה לא אמורה לאבד פונקציונליות נדרשת בזמן שהאינטגרציה נבנית.
- **לבדוק ב־staging:** כניסה מקצה לקצה · **יציאה בשתי השפות** · TOTP · הרשמה · החלפת שפה בתוך כנס · `/studio` · העלאת מדיה בגודל הגבול (סעיף 18) · 404 על slug לא קיים · **`/{locale}/experiences/{slug}`** · **טעינת `/brand/*` ו־`/placeholder/*`** · **לוגו בתוך מייל** · **לוגו באנגלית מגיע ל־`/` ולא ל־`/en`** (5.1) · **ארבעת העמודים המשפטיים עדיין נגישים**.

| מה נשבר | גלגול לאחור | זמן |
|---|---|---|
| כללי proxy | החזרת הקונפיג הקודם + `nginx -t` + reload, או ביטול Origin Rule | שניות |
| Cloudflare Tunnel | הפעלת ה־fallback המתועד (16.5); `netaim26.org` נשאר חי | דקות |
| `NEXT_PUBLIC_SERVER_URL` | החזרת הערך + `pm2 restart hason` | דקה |
| הגירת הנתיבים | `git revert` של ה־commit + build + restart | דקות |
| קישורי footer | `git revert` לקובץ אחד | דקות |
| הגירת טוקנים/עיצוב | `git revert` ל־`globals.css` | דקות |
| **HSTS** | ⚠ **אין גלגול לאחור אמיתי.** דפדפן שקיבל את הכותרת מכבד אותה עד שהיא פגה | **עד שנתיים** |
| תקרות גוף בקשה | החזרת הקונפיג + reload | שניות |
| DNS / tunnel | החזרת רשומות; `netaim26.org` כנפילה | עד שעה (TTL) |
| **מסד נתונים** | ⚠ **אין rollback סכימתי.** אין היסטוריית מיגרציות (סעיף 10) — **שחזור מגיבוי בלבד**, עם אובדן הכתיבות מרגע הגיבוי | לפי גודל |

**כלל:** כל שלב בסעיף 28 חייב להיות הפיך בפעולה אחת. שלב שאינו הפיך — לא לבצע.

**שני חריגים שחייבים להיאמר, כי גרסה 1.0 הציגה אותם כהפיכים:**

1. **HSTS אינה הפיכה.** זו הסיבה שסעיף 19 מדורג, ושהיא **הפריט האחרון** בהשקה ולא חלק מהגדרות הבסיס.

## A. האם אותה פלטפורמה תשרת 2026–2030 בלי תכנון ניתוב מחדש?

**כן, ואומת מול 554 קבצי מקור.** הדפוסים `^/(he|en)/events/[^/]+` ו־`^/(he|en)/experiences/[^/]+` אינם מכירים slug. כנס חדש הוא **רשומה ב־Payload** עם slug ייחודי — ומהרגע שהיא נשמרת, `/he/events/netaim-2030/schedule` עובד בלי לגעת ב־proxy, ב־Nginx, ב־Cloudflare או בקוד. גם קישורי הכניסה במייל נבנים דינמית לפי slug, וגם ה־`events-sitemap.xml` ישאב את הרשימה מ־Payload. התנאי היחיד: אף אחד לא יכניס slug קשיח לשום חוק — ובמסמך הזה אין אחד.

## B. אילו נתיבים שייכים לוורדפרס?

`/` (אנגלית) · `/he/` · `/about-us/` · `/he/מי-אנחנו/` · `/contact-us/` · `/he/צרו-קשר/` · `/privacy-policy/` · `/he/מדיניות-פרטיות/` · `/newsletter/` · `/programs/` · `/he/programs/` וכל פריט תחתיהם · `/events/` ו־`/he/כנסים/` (העמודים עצמם) · `/sitemap.xml` · `/robots.txt` · `/wp-*` · וכל שאר תוכן האתר. **ברירת המחדל היא וורדפרס.**

**שני סייגים מאומתים ומאושרים:**

1. **אין שורש `/en/`.** אנגלית יושבת ב־`/`. לא ייווצר עמוד `/en/` בוורדפרס כדי לרצות את הפלטפורמה — הפלטפורמה מצביעה ל־`/` (5.1).
2. **בעלות משפטית: ⏸ `DEFERRED — FINAL WORDPRESS LEGAL MIGRATION`.** פרטיות ויצירת קשר קיימים בוורדפרס; תקנון ונגישות טרם. עד שלב 14 הפלטפורמה מגישה את שלה, וורדפרס את שלו, ואין הגירה ואין מחיקה (6.3).

## C. אילו נתיבים שייכים לפלטפורמה?

`/{locale}/events/{slug}/*` (**בשתי השפות, כולל `/en/events/…`**) · **`/{locale}/experiences/{slug}`** · `/{locale}/me/*` · `/{locale}/enter` · `/{locale}/connect/*` · `/studio*` · `/admin*` · `/api/*` · `/_next/*` · **`/brand/*`** · **`/demo/*`** · **`/placeholder/*`** · **`/videos/*`** · **`/icon.png`** · **`/apple-icon.png`** · `/events-sitemap.xml` · ⏸ `/{locale}/{privacy,terms,accessibility,contact}` (**DEFERRED — נפילה קיימת עד שלב 14**).

המודגשים נוספו בגרסה 2.0. בלעדיהם התוכנית הייתה מפילה פיצ'ר חי ואת כל הנכסים הסטטיים, כולל הלוגו במיילים.

**הבהרה שחוזרת כי קל לפספס אותה:** העובדה שוורדפרס אינו מגיש שורש `/en/` **אינה** מוציאה את `/en/events/{slug}/*` מבעלות הפלטפורמה. שורש חשוף וקידומת נתיב הם שני דברים שונים (5.1).

## D. איך יעבוד ניתוב `{slug}` דינמי?

ב־proxy: התאמת regex בלבד, שני דפוסים. באפליקציה: `[slug]` הוא סגמנט דינמי של App Router; העמוד קורא אותו מ־`params` ושואל את Payload לפי `slug` (שדה `unique` + `index`). אין טבלת מיפוי, אין רשימה, אין קונפיגורציה. הוספת כנס = יצירת רשומה.

אחרי ההגירה גם העמודים המזוהים (`program`, `speakers`, `speakers/{id}`, `info`) יורשים את ה־slug **מהנתיב** דרך קבוצה מקוננת — ולא מ־Global.

## E. איך האימות ימשיך לעבוד בלי חשבונות וורדפרס?

בלי לגעת בו. אותו magic link, אותם קוקיז, אותו טוקן חתום, אותו מסד. וורדפרס לא יודע על קיומם של משתתפים ולא נדרש שידע. **השינוי היחיד:** `NEXT_PUBLIC_SERVER_URL`. נבדקו כל שמונת השימושים בו, ולא נמצא אף תלות נוספת בדומיין — האפליקציה אינה מסיקה host מכותרות, ושומר ב־CI אוכף שכל הפניה מוחלטת עוברת ב־`siteOrigin`.

## F. איך עמודי האתר הכלליים יישארו בלעדית בוורדפרס?

**לעמודים הארגוניים — About, Programs, Newsletter — שלוש שכבות.** **ראשית**, ברירת המחדל ב־proxy היא וורדפרס. **שנית**, האפליקציה אינה מחזיקה מקבילה להם בכלל. **שלישית**, אין כפילות תוכן.

**סייג לשכבה הראשונה:** היא עובדת רק אם רשימת סעיף 3.2 **מלאה ומתוחזקת**. בגרסה 1.0 היא לא הייתה, ו"ברירת המחדל לוורדפרס" הייתה מפילה את `experiences` ואת כל הנכסים הסטטיים.

**לעמודים המשפטיים — התשובה שונה, ובמכוון: ⏸ `DEFERRED`.** עד שלב 14 **שתי המערכות מחזיקות תוכן משפטי באותו דומיין**, וזה מקובל ומתוכנן: הפלטפורמה ב־`/{locale}/privacy|terms|accessibility|contact`, וורדפרס ב־`/privacy-policy/` ו־`/he/מדיניות-פרטיות/`. ההצדקה: מחיקת עמודי הפלטפורמה לפני שקיימת מקבילה מאושרת הייתה משאירה את האתר בלי מסמכים שנדרשים בחוק.

**המחיר של הדחייה, ואיך הוא מנוהל:** תוכן משפטי כפול על דומיין משותף פוגע ב־SEO. לכן העמודים של הפלטפורמה **יוצאים מה־sitemap** בשלב 8, ונשקלת גם הצהרת `robots: index:false` עליהם (21.5). הם נשארים **נגישים במלואם** — אי־הכללה ב־sitemap אינה חסימה, וזו בדיוק הנקודה. **הבלעדיות מושגת בשלב 14, לא לפניו.**

## G. איך עמודי הכנס הציבוריים יעברו תחת `/events/{slug}/`?

**תיקון שם:** הם אינם ציבוריים — כולם מוגנים ב־`requireParticipant`.

ההגירה: **קבוצת נתיבים מקוננת** `events/[slug]/(experience)/`, ולא layout מעל `events/[slug]`. הסיבה מחייבת: layout במפלס `[slug]` יעטוף גם את דף הנחיתה הקינמטי ויציב עליו chrome שני. בתוך הקבוצה, מקור הכנס מתחלף מ־`Site.activeConference` ל־`params.slug`. הנתיבים המתקבלים עובדים לכל כנס ולכל שנה. הנתיבים הישנים **נעלמים** — לא מנותבים, ולא מופנים.

## H. איך שני השרתים יתקשרו בבטחה?

**Cloudflare Tunnel** — אושר. חיבור יוצא מוצפן מהשרת אל Cloudflare, אפס פורטים נכנסים, שרת המקור אינו ניתן לגילוי, וזמינות ה־tunnel מנוטרת. **נפילה מתועדת:** HTTPS ל־origin עם תעודה תקפה ל־`netaimolami.org` **במקור**, Full (strict), וחומת אש שמגבילה 443 לטווחי Cloudflare.

**נימוק שנמצא בקונפיג הקיים:** התעודה במקור הונפקה ל־`netaim26.org` בלבד, ולכן הנפילה דורשת תעודה חדשה ותחזוקתה. ה־Tunnel מייתר את זה. **HTTP גלוי נשלל מפורשות** — התעבורה נושאת קוקיז של session.

## I. אילו שינויים בדיוק נדרשים לפני ייצור?

1. הגירת `(experience)` לקבוצה מקוננת + **24 אתרי הקישור** + ה־snapshot. **ארבעת קישורי ה־footer המשפטיים אינם בכלל הזה** — הם בשלב 14.
2. **מפת `WORDPRESS_HOME` מודעת שפה** (5.1) — `he → /he/`, `en → /`. מתקנת 404 ביציאה באנגלית.
3. `NEXT_PUBLIC_SERVER_URL=https://netaimolami.org`.
4. Cloudflare Tunnel + ניטור `cloudflared`.
5. כללי ניתוב לפי סעיף 3.2 **במלואו** — כולל `experiences` וארבעת מרחבי הנכסים.
6. חומת אש: 3000 ו־5432 סגורים; אפס פורטים נכנסים.
7. חוקי cache (bypass ל־`/me`, `/api`, `/studio`, `/admin`; קאש ארוך לנכסים).
8. `events-sitemap.xml` דינמי + `robots.txt` שחוסם את הנתיבים המוגנים + **הוצאת העמודים המשפטיים מה־sitemap** (21.5).
9. `server_name` מוצהר, `proxy_buffering`, ותקרות גוף בקשה **לפי נתיב**.
10. **הסרת כותרת ה־HSTS מהאפליקציה**, והפעלה מרכזית בלי `preload`.
11. פריט "כנסים" בשני תפריטי וורדפרס + `/events/` + `/he/כנסים/`.
12. `curl -I` ל־`/` ול־`/he/` — שתיהן 200.
13. צ'קליסט האבטחה בסעיף 30.
14. ⏸ **ההגירה המשפטית הסופית** (28.14) — חמישה צעדים, **שער חובה לפני cutover**, באחריות ארגון וורדפרס.

**לא נדרש:** `basePath` · `assetPrefix` · שינוי middleware · שינוי i18n · שינוי אימות · שינוי סכימה · מיגרציה · הגירת משתמשים · שינוי בכתובות נכסים · **יצירת עמוד `/en/` בוורדפרס** · **יצירה או מחיקה של תוכן משפטי עכשיו**.

## J. מה אסור לשנות?

את האימות ומחזור ה־session · את מרחב הטוקנים החתומים · את סכימת Payload ואת המיגרציות (**ואת `Site.activeConference` — השדה נשאר**) · את ה־access control · את `participant-gate.ts` · את ה־middleware ואת ארכיטקטורת ה־i18n (`localePrefix: 'always'`, `he` כברירת מחדל) · את חמשת מודולי ה־engine · **את שמות הנתיבים העובדים** — `/program`, `/schedule`, `/workshops`, `/my-activities`, `/speakers`, `/me/speakers`, `/me/profile`, `/enter`, `/register` (החלטות 4 ו־5: **לא ממזגים ולא משנים שם**) · **את כתובות הנכסים הסטטיים** (החלטה 2) · את מבנה העמודים, הסקשנים והווידג'טים בוורדפרס · ואת עקרון ריבוי הכנסים: **אף slug לא ייכנס לשום חוק, בשום שכבה.**
