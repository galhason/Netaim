# Hason — Experience Language

The product vocabulary (Product Direction Addendum). Organizers create experiences; they do not manage data. This glossary governs all organizer-facing copy, documentation, and future Studio UI. Technical documents may keep technical terms; the product never shows them.

| Instead of | Hason says | Where |
|---|---|---|
| Builder / Editor | **Experience Composer** | the composing workspace |
| Preview | **Experience Preview** | device/locale/state preview mode |
| Publish | **Launch** (Launch Experience) | the go-live action and its confirmations |
| Dashboard / Home feed | **Continue creating** | the Home's leading section |
| CMS / admin | **Studio** | the entire creator product |
| Content block / document / field | scene, chapter, story, detail | composer copy |
| Users (attendees) | participants, guests | registration surfaces |
| Records / entries | people, places, moments | everywhere |
| Settings (event feel) | **Experience Identity** | the creative identity of the event |
| Validation / QA | **Experience Inspector** | quality-of-experience guidance (future) |

Rules: actions keep the same name through a whole flow (the button that says Launch produces "Launched"); status is expressed as language, not badges ("Ready to launch", "Waiting for review"); errors state what happened and the way forward, in the product's calm voice. Terminology changes require updating this document first.
